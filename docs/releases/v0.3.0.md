# Watermelon v0.3.0

Watermelon now defaults to strict network enforcement and supports both macOS
and Linux hosts. This release also adds project-owned named VMs, optional
project mounts, explicit guest workdirs, safer applied-policy verification, and
the Linux `watermelon-nfqd` sidecar used by `ask` mode.

## Action required when upgrading

Recreate every existing Watermelon VM before using it with v0.3.0. Watermelon
cannot prove the effective policy of VMs created before versioned policy
snapshots, so `run`, `exec`, and `code` deliberately refuse to reuse them. First
update any legacy `[mounts]` targets as described below; v0.3.0 will reject the
old target when an operation requires valid config. As a safety measure, `run`,
`exec`, or `code` may also stop a running VM whose project ownership can be
verified.

Preserve any VM-local files you need, then run this from each project:

```bash
watermelon destroy --force
watermelon run
```

Destroying the VM deletes VM-local state. It does not delete the host project
or other host paths mounted by the project.

Omitting `security.enforcement` now selects `fail`, which blocks and records new
external connections not covered by the allowlist. An explicit
`enforcement = "log"` remains permissive discovery mode. Configurations generated
by older versions normally contain an explicit `log`; change that value to
`fail` if you want the strict behavior, review the allowlist, and then recreate
the VM.

## Additional mount target migration

Targets in `[mounts]` must now be `/mnt/watermelon` or one of its descendants.
This prevents a configured host mount from replacing guest system, home,
policy, or project paths.

For example, migrate an old entry like this:

```toml
[mounts]
"~/.gitconfig" = { target = "/home/dev/.gitconfig" }
```

to a dedicated target:

```toml
[mounts]
"~/.gitconfig" = { target = "/mnt/watermelon/gitconfig" }
```

Applications do not automatically discover configuration at the new target;
point the relevant application or environment variable at the mounted path.
After changing mount targets, recreate the VM so Lima applies the new mounts.

## Release artifacts

This release publishes Watermelon CLI binaries for Darwin and Linux on amd64
and arm64, plus Linux amd64 and arm64 `watermelon-nfqd` binaries for `ask` mode.
