# Watermelon v0.4.1

Watermelon v0.4.1 is the first published v0.4 release. It adds a host-readiness
doctor, safer installation and release artifacts, project-root discovery from
subdirectories, correct guest exit-code propagation, and a broad hardening pass
across interactive network decisions, configuration validation, SSH
integration, and policy logging.

The `v0.4.0` tag did not publish a GitHub release or artifacts because its
release-only real-VM checks failed before the build and publication jobs.
v0.4.1 carries the same product changes with corrected release validation.

## Action required when upgrading

Recreate existing Watermelon VMs after upgrading. Several fixes in this release
change guest-side networking, provisioning, and logging components that cannot
be replaced safely in an already-created VM. This is especially important for
VMs using `security.enforcement = "ask"`, whose in-guest network interceptor is
installed during VM creation. Watermelon treats snapshots written by v0.3.x as
unverified and returns a recreation instruction instead of reusing those VMs.

Preserve any VM-local files you need, then run this from each project using its
default or configured VM name:

```bash
watermelon destroy --force
watermelon run
```

Destroying the VM deletes VM-local state. It does not delete the host project
or other host paths mounted by the project. If the VM was selected with an
explicit CLI `--name`, pass the same `--name` to both commands.

Watermelon now requires stable Lima 2.0.0 or newer. On macOS, Watermelon
requires macOS 13 or newer. Run `watermelon doctor` before recreating VMs to
check the host, Lima backend, SSH client, architecture, and QEMU availability.

## Host diagnostics and installation

The new project-independent `watermelon doctor` command reports whether the
host is ready without creating or changing a VM. Use `watermelon doctor --json`
for a versioned, machine-readable report.

The shell installer now validates the host before downloading artifacts,
supports an absolute `WATERMELON_INSTALL_DIR`, avoids assuming `sudo`, chooses
the guest network-interceptor asset from Lima's reported architecture, and
verifies the exact installed binary. Tagged `go install` builds can securely
download and validate the matching interceptor when a new `ask`-mode VM needs
it.

## CLI behavior and project discovery

- Commands launched below a project root discover the nearest trusted
  `.watermelon.toml` and use that canonical root consistently for VM identity,
  mounts, policy state, logs, and provisioning.
- `watermelon exec` and other guest handoffs preserve guest exit statuses,
  including conventional signal exit codes.
- CLI errors are printed once. Invocation mistakes include relevant usage,
  while runtime and policy failures remain concise.
- Commands that take no positional arguments now reject stray operands before
  resolving or mutating VM state.

## Ask-mode safety and reliability

- On Linux, prompts take exclusive control of the foreground terminal while
  redirected stdin remains dedicated to the guest. Headless decisions fail
  closed.
- **Always Allow and Save** distinguishes the immediate endpoint decision from
  the broader host-only rule written to `.watermelon.toml`, preserves unrelated
  formatting and permissions, and prints an exact recreation command.
- TCP and DNS parsing, hostname attribution, replay handling, decision caches,
  authenticated verdict transport, and NFQUEUE failure propagation are more
  defensive and bounded.
- Stale or mismatched network-interceptor binaries are rejected or replaced
  only with a release asset whose digest and Go build identity match the CLI.

## Additional hardening

Configuration validation now rejects ambiguous tool mappings, unsafe or
duplicate ports and mounts, malformed resource sizes, excessive process rules,
and internal image or command collisions. Provisioning uses direct argument
vectors where supported and records exact trusted script bytes.

SSH include management and rollback, VM identity paths, and network log access
now use stricter ownership, no-follow, atomic publication, and bounded-file
checks. Policy logs retain their active writer when cleared and cap retained
data. Release CI covers unit, race, vet, vulnerability, Lima compatibility,
cross-platform artifacts, installer smoke tests, and real-VM security flows.

## Release artifacts

This release publishes Watermelon CLI binaries for Darwin and Linux on amd64
and arm64, plus Linux amd64 and arm64 `watermelon-nfqd` binaries for `ask` mode.
